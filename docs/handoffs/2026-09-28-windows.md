## What the Windows session is for

1. **Help the owner run the Windows tests:** `docs/plans/3.1.0/WINDOWS-TESTS.md`.
   - Native Windows is **not** supported by the xezar engine 0.19.0 (it refuses win32; kit checks
     need bash and POSIX). Engine, leader and workflows run in **WSL2 (Ubuntu)**; clone repos in
     the Linux home (`~`), not under `/mnt/c`.
   - Only the Erfana Electron e2e tests (github.com/qodeca/erfana) run on native Windows
     (PowerShell): `npm ci`, `npx electron-vite build`, `npx playwright test --project=electron`.
   - The upgrade prompt's step 1 needs the `v3.1.0` release, which does not exist yet. For a dry
     run on a throwaway clone, use a `develop` checkout with a **local-only** `v3.1.0` tag and skip
     only the release-authenticity checks. Never push that tag.
2. **Record each failure with its exact output**, fix what belongs to this repo in a PR into
   `develop`, and report plainly.
3. **When the owner says "Windows tests done", do the release** from draft PR #101:
   1. Set the real release date (CHANGELOG, compatibility ledger).
   2. Rebuild the kit index on the release head: `node scripts/build-kit-index.mjs` in a full clone
      with tags and a local-only `v3.1.0` stand-in tag on that head; commit; then
      `node scripts/build-kit-index.mjs --check --ref <release head>` must pass. (Every PR in the
      last two nights rebuilt the index on its own branch, so the committed index names a commit
      that squash-merging removed. This rebuild fixes that.)
   3. Merge #101 into `main`, tag the merge commit `v3.1.0`, publish the release with the notes
      draft and `Release-Commit: <that sha>`.
   4. Re-run the index builder with the real tag and commit the refreshed index to `develop`
      (`upgrade/README.md` → "Releasing a version the tool upgrades to").
4. **After the release:** the owner upgrades live projects one at a time (8cli → cmplus → Erfana →
   others) with `upgrade/UPGRADE-PROMPT.md`. Dry runs on cmplus said the tool is ready; expect
   about 41 safety files for the owner to decide. A cmplus decision sheet exists only on the Mac
   (not in this public repo) – ask the owner to copy it over if wanted.

## Working rules (decided by the owner; not all are written elsewhere)

- **Gates:** run each command from `jq -r '.validation.commands[]' .xezar/pipeline/config.json`
  one at a time (23 commands). Never batch them in a shell loop (false `rc=127`).
- **The guard suite runs nightly only** (`.github/workflows/nightly-guards.yml`, #102). Do not run
  `scripts/test-guards.mjs` per change; still run `node --check scripts/test-guards.mjs` after
  editing it, and give every new guard a deliberate-break case. The nightly schedule starts only
  once the workflow reaches `main` (GitHub runs schedules from the default branch). Last full local
  run: all guards caught their defects on `develop` at #119.
- **Merges:** PRs go into `develop`, squash-merged once the fast CI (about 2 minutes) is green.
  The owner approved merging when green without asking each time.
- **Kit changes:** any change under `skills/xez-onboard-opinionated/kit/**` makes
  `test-upgrade.mjs` report the 3.1.0 kit index stale – rebuild it last, as above, and list the
  file in the fitting 3.1.0 `UPGRADE_NOTES.md` entry (`test-upgrade` check 6 enforces this).
- **Owner decisions kept from the night of 2026-09-27/28:** guard suite nightly; a repair step
  merges the base into an older PR when kit scripts changed (adds a merge commit); owner config
  files are not drift-checked; an unknown project version is worked out from file evidence.
- **Talking to the owner:** plain, short sentences (ASD-STE100 style); every question through
  `AskUserQuestion` with at most two options and a recommendation; English only.
- **Delete only with the owner's OK.** The bash-safety hook blocks `rm -rf` on some paths – use a
  scratch folder for throwaway clones and leave them.

## Environment notes for Windows

- Use WSL2 for this repo's scripts too: `scripts/lint.sh` and the kit checks need bash; the

  `AGENTS.md`).
- `gh` must be logged in inside WSL (`gh auth login`); Node LTS via nvm; `jq` installed.
- Claude memory from the Mac does not carry over. The rules above replace it.
