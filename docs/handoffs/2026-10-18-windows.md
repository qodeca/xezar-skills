## What the Windows session is for

Do them in this order. Each fix goes in its own PR into `develop`, with the gate green.

1. **The upgrade tool must never run a program from the project (security).** On Windows, a
   program started without a full path is looked up in the current folder first. The tools start
   bare `git` with the project as the current folder, so a `git.exe` committed in the project
   would run. Places: `upgrade/tools/lib/paths.mjs` (~:90-100), `upgrade/tools/lib/context.mjs`
   (~:192), `upgrade/tools/verify.mjs` (~:84, :89-90), `upgrade/tools/apply.mjs` (~:162), and
   `xezar` in `upgrade/tools/plan.mjs` (~:247-250). The tool's own comment at `verify.mjs`
   (~:57-59) already says this about `node`.
   - Fix: start git with the clone (or a temporary folder) as the current folder and pass
     `-C <project>`, or resolve git to an absolute path first. Use `scripts/lib/platform.mjs` for
     path and program lookup.
   - Prove it: a test in `scripts/test-upgrade.mjs` that puts a fake `git.exe` (or `git.cmd`)
     in a fixture project, which writes a marker file when run, and checks that detect, plan,
     apply and verify never run it. Add a deliberate-break case in `scripts/test-guards.mjs`.
2. **Check the CRLF fix on real Windows.** Make a throwaway project from the 3.0.3 fixture
   (`scripts/fixtures/upgrade/3.0.3/`), commit `.xezar/docs/leader-guide.md` with CRLF line ends
   (`git -c core.autocrlf=false`), and run detect, plan, apply and verify from a `develop` clone.
   It must pass with no `owner-rules-changed`. Also try a checkout with `core.autocrlf=true`.
3. **One real upgrade, end to end, on Windows in Git Bash.** Use a throwaway copy of a 3.2.0
   project (or the 3.2.0 fixture once it is on `develop`), clone `xezar-skills` as
   `upgrade/README.md` says (`-c core.autocrlf=false`), and follow `upgrade/UPGRADE-PROMPT.md`.
   Note every step that fails or reads wrongly on Windows: the PowerShell leader check in step
   0.4, the git hook reads in step 0, `mktemp -d`, paths with spaces, and the report. Fix what
   belongs to this repo; record the rest.
4. **#230 – a Codex review step on native Windows cannot post its comment or write its
   verdict.** The engine side is qodeca/xezar#1089. The 3.2.0 changelog (`CHANGELOG.md` ~:37-41)
   says "the kit follows in 3.2.1", but 3.2.1 did not carry it.
   - If xezar#1089 has shipped: make the kit change #230 asks for, and add an
     `UPGRADE_NOTES.md` entry keyed by the symptom.
   - If it has not: add only the `UPGRADE_NOTES.md` symptom entry ("on Windows a Codex review
     posts no comment and writes no verdict" → route Windows reviews to Claude until the fix),
     and ask the owner whether to correct the released 3.2.0 changelog line.
