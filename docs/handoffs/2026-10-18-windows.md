## What the Windows session is for

Do them in this order. Each fix goes in its own PR into `develop`, with the gate green.

1. **The upgrade tool must never run a program from the project (security).** On Windows, a
   program started without a full path may be looked up in the current folder first (check how
   Node's `execFileSync` searches on Windows; the tool's own comment at `upgrade/tools/verify.mjs`
   ~:57-59 says this holds for `node`). The tools start bare `git`, and some start it with the
   project as the current folder, so a `git.exe` committed in the project could run. Places:
   - the shared helper `git(args, cwd)` in `upgrade/tools/lib/hash.mjs` (~:36), called with the
     project as `cwd` from `lib/paths.mjs` (~:91, :95), `lib/context.mjs` (~:192) and
     `verify.mjs` (~:84, :92-93);
   - `execFileSync("git", …)` in `lib/paths.mjs` (~:116) and `apply.mjs` `gitMerge` (~:201);
   - `xezar` / `xez` in `plan.mjs` `engineVersion` (~:249-252), with no `cwd`, so it runs in the
     folder the tool was started from – the project.
   - Fix: resolve `git` (and the engine binary) to an absolute path from `PATH` once, skipping
     the project folder, or start git with the clone as the current folder and pass
     `-C <project>`. Use `scripts/lib/platform.mjs` for path and program lookup.
   - Prove it: a test in `scripts/test-upgrade.mjs` that puts a fake `git.exe` and `git.cmd` in
     a fixture project, each writing a marker file when run, and checks that detect, plan,
     apply and verify never run them. Add a deliberate-break case in `scripts/test-guards.mjs`.
2. **Check the CRLF fix on real Windows, and run the tests that skip there.**
   - Make a throwaway project from the 3.0.3 fixture (`scripts/fixtures/upgrade/3.0.3/`), commit
     `.xezar/docs/leader-guide.md` with CRLF line ends (`git -c core.autocrlf=false`), and run
     detect, plan, apply and verify from a `develop` clone. It must pass with no
     `owner-rules-changed`. Try a checkout with `core.autocrlf=true` too.
   - `scripts/test-upgrade.mjs` sections 5a (old git without `--zdiff3`, and "a failed merge
     writes nothing") and 5g (paths git refuses in `check-ignore`) skip on Windows, because their
     stand-in git is a shell script. Make them run on Windows (a `git.cmd` stand-in, or a Node
     script started through `scripts/lib/platform.mjs`), and confirm they pass. The matching
     cases in `scripts/test-guards.mjs` are POSIX-only for the same reason.
3. **One real upgrade, end to end, on Windows in Git Bash.** Use a throwaway copy of the 3.2.0
   fixture (`scripts/fixtures/upgrade/3.2.0/`, from #255) made into a git repository, clone
   `xezar-skills` at `develop` as `upgrade/README.md` says (`-c core.autocrlf=false`), and follow
   `upgrade/UPGRADE-PROMPT.md` with `--target` set to the clone's `package.json` version. Step 1's
   release verification cannot pass on `develop`: skip only that check and say so in the report.
   Note every step that fails or reads wrongly on Windows: the PowerShell leader check in step
   0.4, the git hook reads in step 0, `mktemp -d`, paths with spaces, the stop-and-resume path in
   step 0.2, and the report. Fix what belongs to this repo; record the rest.
4. **#230 – a Codex review step on native Windows cannot post its comment or write its
   verdict.** The engine side is qodeca/xezar#1089, still open on 2026-10-18. The 3.2.0 changelog
   (`CHANGELOG.md` ~:37-41) says "the kit follows in 3.2.1", but 3.2.1 did not carry it.
   - If xezar#1089 has shipped: make the kit change #230 asks for, and add an
     `UPGRADE_NOTES.md` entry keyed by the symptom.

     posts no comment and writes no verdict" → route Windows reviews to Claude until the fix),
