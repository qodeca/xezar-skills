# Locally relevant project guidance

Use only after the software/Git/package-manager applicability check and within authorized setup. A missing document is not a defect and does not authorize creating a process.

1. Read the user's requested outputs, existing guidance, repository layout, verified commands and public contracts. Resolve which source is authoritative; link it instead of copying rules into a second file.
2. Propose only content that fills a demonstrated local need. Select filenames and locations from project conventions or the user's choice. No fixed set of document types is required.
3. Derive each statement from observed project facts or a recorded owner decision. Separate unknowns from established rules. Do not infer a mandatory review team, tracker, stage sequence or label taxonomy.
4. Show the proposed content and paths before writing unless already authorized. Preserve existing files; an update needs its own authorization. Under unattended defaults, omit unrequested guidance and report that omission.

Possible content, only when relevant and requested:

- Working guidance: project purpose, actual entry points, architectural boundaries and verified checks. A client may discover `AGENTS.md` or `CLAUDE.md`; these are client capabilities, not required outputs. Use the client's existing file when supplied.
- Delivery guidance: the project's actual authorization, verification, review and handoff requirements. `references/sdlc-template.md` is an optional software example to adapt, not a required lifecycle or filename.
- Review guidance: demonstrated correctness, security and compatibility risks, linked to existing checks. Set `reviewChecklist` to the chosen path when appropriate.
- Compatibility guidance: actual public surfaces and the owner's established migration/deprecation policy. Do not invent a policy merely to fill a template.

For non-software work, return to the task's requested brief, plan, report or artifact and its domain-specific evidence. Do not generate software governance documents, config or labels.
