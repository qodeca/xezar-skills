# Onboarding result

Lead with the actual outcome: files prepared, already current, report-only re-check, partial failure or blocked. Name the project/task and mode, chosen client/base when relevant, engine/kit identities and the evidence location.

## Changed files

List each changed file and its purpose; link the reviewable diff. Identify applied, pending and failed files separately after a partial write. A worktree candidate is not yet integrated into the primary project.

## Verification

List each actual check, its result and evidence. Separate detected commands from executed checks, and static fixture checks from live client/delivery verification. State whether all promised checks completed; never translate unknown or unavailable into passed.

## Remaining user steps

Use a numbered list, omitting already completed or inapplicable actions:

1. Review and integrate the prepared project changes through the project's chosen process.
2. Review the selected client's project trust/MCP prompt and log in yourself; install missing client/adapter prerequisites if needed.
3. Start the selected client in the integrated project using its installed connection reference, make a tool call, then deliberately attach the leader through the supported control.
4. Confirm the correct project, connection owner and actual event delivery/replay before relying on leader coordination.

Independent mode needs no leader trust/MCP/attachment steps. Offer an evidence-backed first ordinary task from the examples; do not launch it without task authority.

## Not done and why

Name relevant omitted work: optional pipeline not chosen, missing companion/source, unavailable checks, home configuration, trust, login, attachment or publication. Include the next action for every blocker. For re-checks distinguish proposed versus applied changes and report-only completion; record no successful-check timestamp on partial failure.

## Resume

When anything remains, save task identity, decisions, source/local digests, valid preview, applied/pending paths and remaining checks in the existing checkpoint. A completion marker certifies only this scoped task, never business acceptance or future publication.
